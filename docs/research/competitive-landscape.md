# Competitive landscape — AI agent workflow platform for automated bug fixing

*Researched 2026-09-21. Every URL was fetched on that date unless marked otherwise. "unknown" = not verifiable from an official source. Numbers are as published; third-party figures are flagged.*

**Our product, for reference:** Go + React on the `toolnexus` agent SDK. A step = prompt + scoped skills/MCP tools + JSON-schema output contract. Step state in Postgres (`workflow_runs` / `step_runs` with `output jsonb`, `attempts`, `turns`, statuses incl. `awaiting_approval` / `needs_input`), artifacts in S3. First workflow: validate → reproduce → draft PR → validate PR → publish PR.

## 3. Gaps / whitespace — honest version

**Where incumbents already do it (don't pretend otherwise):**
- **User-defined multi-step coding workflows with approval gates exist**: Archon (OSS, YAML, approval nodes, worktrees, MIT), Zenflow (commercial, custom steps + gates), Windmill (generic, but AI-agent step *with JSON schema* + suspend/approval, Rust). Tembo and OpenHands Automation Server cover event → agent → PR with confirmation.
- **Schema-enforced step output exists in pieces**: Codex `--output-schema`, Windmill agent step, LangGraph `response_format`, MS-AF `response_format`.
- **Self-host is common** among OSS (OpenHands, SWE-agent, Archon, Windmill, n8n-with-caveats).

**Where nobody has all of it together:**
1. **Per-step scoped skills/tools × JSON-schema contract × durable Postgres state × approval gate × self-host, in one runtime.** Archon has steps+gates but is Bun/TS, drives external CLIs (Claude Code/Codex) as black boxes, and doesn't document schema validation. Windmill has schema+approval but is a generic job engine with no repo/PR/sandbox model. Zenflow is a desktop app. gh-aw is one-agent-per-workflow and GitHub-only.
2. **Typed hand-off between coding steps.** Every product passes free text (or a git branch) between "plan" and "implement". A `reproduce` step that must emit `{repro_cmd, exit_code, evidence_artifact}` before `fix` may start is not on the market.
3. **Verification as a first-class, schema-checked step** (not "runs tests if env allows"). Seer runs zero tests; Copilot/Devin/Jules/Cursor make it prompt-dependent; only Tembo/Kiro/Zenflow name a verifier.
4. **Language-neutral SDK.** Agent integrations are Python-first (Temporal's agent plugins are Python-only; LangGraph Py/TS; MS-AF Py/.NET). A byte-identical SDK across 7 languages has no counterpart; the closest is ADK (5 languages, different surfaces).
5. **No orchestration server.** Temporal, LangSmith Deployment, Prefect, n8n queue mode, Trigger.dev all need a server + Redis/ClickHouse. Inngest ships a single Go binary but is SSPL and generic. A single Go binary + Postgres + S3 for *coding* workflows is open.
6. **Commercial licensing whitespace**: n8n (SUL) and Dify forbid multi-tenant hosting; Inngest is SSPL; LangSmith self-host is Enterprise-only. Apache-2/MIT + self-host + commercial-friendly is thin among the *hosted-workflow* tier.

**Threats:** Archon's 23.5k stars mean the "harness builder" category has demand and an OSS default. Claude Code Auto-fix PRs + Managed Agents and GitHub's Agent HQ/gh-aw can absorb the simple case (CI fails → agent fixes). Our wedge must be the typed, gated, multi-step pipeline plus footprint, not "an agent that opens PRs".

## 5. Naming / positioning + features to steal

**Taglines (pick one):**
1. "Typed pipelines for coding agents. One Go binary, your Postgres, your repo."
2. "n8n for bug fixes — every step a contract, every merge a human."
3. "Reproduce before you fix, verify before you ship: coding workflows with schema-checked hand-offs."

**Five features to steal:**
1. **Git worktree per run, N runs in parallel with zero conflicts** — Archon's "run 5 fixes in parallel" ([repo](https://github.com/coleam00/archon)). Map to our `WorkDir` per `run_id`.
2. **Safe-outputs pattern** — agent step produces *proposed* writes; a separate, minimally-privileged job validates and applies them (gh-aw) ([site](https://github.github.com/gh-aw/)). Our `publish PR` step should be exactly this: no GitHub write token in the LLM steps.
3. **Loop-until-predicate with a hard cap** — Archon `loop … until: tests pass`; Cursor Bugbot Autofix max 3 attempts; Codegen CI auto-fixer ≤3 retries then escalate ([Bugbot](https://cursor.com/docs/bugbot), [Codegen](https://docs.codegen.com/capabilities/capabilities)). Expose `max_attempts` on `step_runs.attempts` and escalate to `needs_input`.
4. **Fixability score + auto-trigger thresholds** — Seer only auto-runs at ≥10 events / 14 days / fixability threshold ([docs](https://docs.sentry.io/product/ai-in-sentry/seer/issue-fix/)). Make `validate bug` emit `fixability: 0–1` and let the workflow gate on it.
5. **Approval from where the human already is** — Tembo accepts/rejects via Slack, Linear or GitHub ([blog](https://www.tembo.io/blog/multi-agent-ai-coding-workflows)); Prefect auto-generates a form from the `wait_for_input` Pydantic model ([docs](https://docs.prefect.io/v3/advanced/interactive)). Render our `needs_input` schema as a form in React *and* post it to Telegram/Slack with a resume URL (n8n `$execution.resumeUrl` pattern).
