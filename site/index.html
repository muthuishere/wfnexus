Describe it. Claude builds it. You approve it.

A real Claude Code session, recorded unedited except for speed. Priya asks for her Friday release-notes chore as a workflow. Claude builds a five-step wfnexus workflow, runs it on a free model, stops at a human approval gate, and publishes it to the team's git registry.

What the workflow does

1 · Gather

The week's commits from git log, no merges.

2 · Classify

Each commit labelled feature, fix, security, breaking or internal by a calibrated classifier (jev-1.13).

3 · Draft

Customer-facing notes written by an agent on a free model. Internal commits left out.

4 · Review

A second agent checks every claim against the actual commit. 6 of 6 backed.

5 · Gate, then publish

Nothing is written until a human approves. Then RELEASE_NOTES.md is committed.

Run it yourself

wfx adapters                      # devin, opencode, codex — which are installed
wfx models opencode-acp --free    # free models the agent offers
wfx run release-notes -f          # run it, follow the log
wfx approve <run> --step publish  # the human gate
